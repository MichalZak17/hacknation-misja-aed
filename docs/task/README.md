# Zadanie konkursowe — Misja AED „Dane na ratunek”

Organizer's full brief: [zadanie-konkursowe-misja-aed.pdf](zadanie-konkursowe-misja-aed.pdf) (HackNation 2026, Ministerstwo
Cyfryzacji). Below is a faithful summary so agents don't have to re-read the PDF; the PDF wins if they ever disagree.

## Challenge

Build a solution that makes it easier to collect AED (defibrillator) data on **dane.gov.pl**: one nationwide, open, as
current as possible dataset.

- **Collect data from many scattered sources, stating each source's reference scope** ("ze wskazaniem ich
  referencyjnego zakresu").
- **Integrate information from every data holder (dysponent) into one dataset.**
- **Design a reference data scope (wzorcowy zakres danych)** so that every organisation publishes AED data on
  dane.gov.pl the same way.
- **Campaign:** a name and logo for an action that encourages data holders to share AED data, plus a brand book (colours,
  clear space, minimum size, forbidden uses, 3–5 sentence concept description).

Users: emergency services, and anyone who needs to find the nearest working, accessible AED. The brief stresses
*where it is, whether it is accessible (e.g. not locked) and whether it works*.

## Deliverables (wymagania formalne)

- Detailed description and project title.
- Presentation: ≥ 5 slides with evidence that technical requirements are met (screenshots); functionality description
  including user steps; list of limitations (if any).
- Working prototype.
- Reference data scope as an **xlsx** table.
- Source code.
- Logo in .jpg, .png, .pdf and an open format; brand book in .pdf.

## Technical requirements

- Published data must be **machine-readable** (no pdf/doc), except the logo and brand book.
- Compliance with how dane.gov.pl works.
- Current **WCAG**, responsive (desktop + mobile), good UX.
- AI may be used, but the final work must be the team's own analysis and authorship.

## Validation

Running the prototype and checking technical requirements and functionality.
